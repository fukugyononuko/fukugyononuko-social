# 0. 要件定義

## 0.1 背景

運営者「副業のぬこ」は、複数の SNS（X、Threads など）で発信している。投稿づくりは AI で補えるが、次の 2 つは人の手では続かない。

- **計測**：どのチャネル・どの投稿が届いたかを、毎週の数字で残す。本人だけが見られる数字（プロフィールのクリックなど）は、投稿から 30 日を過ぎると取れなくなる（X の場合）。
- **投稿**：同じ文章を複数のチャネルに出す。ただし、名義で出す文章は、本人が承認してから出す。

このシステムは、計測と投稿をまとめて扱う。本人の時間は、返信や会話に回す。

## 0.2 ビジネス要件（BR）

| ID | 要件 |
| --- | --- |
| BR-01 | チャネルごと・投稿ごとの効果を、数字で比べて判断できる |
| BR-02 | 投稿と計測に、人の手間をかけない（承認を除く） |
| BR-03 | 本人が承認していない文章や、個人情報を含む文章は、決して公開しない |
| BR-04 | 費用を小さく保ち、上限を超えない |
| BR-05 | チャネルの追加や、動かす場所の移行（Mac から Google Cloud）を、全体を作り直さずにできる |
| BR-06 | 認証情報と、本人だけが見られる数字を漏らさない |

## 0.3 機能要件（FR）

| ID | 要件 | 上位 | 状態 |
| --- | --- | --- | --- |
| FR-01 | アカウントの数字（フォロワー、フォロー、投稿数）を取得する | BR-01 | 初期 |
| FR-02 | 直近の自分の投稿ごとに、公開の数字（表示、いいね、返信、リポスト、引用、ブックマーク）と本人だけの数字（プロフィールのクリック、リンクのクリック）を取得する | BR-01 | 初期 |
| FR-03 | 取得した値を、取得した時刻つきで保存し、時系列で残す | BR-01 | 初期 |
| FR-04 | 月ごとの集計（アカウントの数字、その月の投稿の合計）と、直近の投稿の一覧を作り、運営者のノートに書き出す | BR-01 | 初期 |
| FR-05 | 計測を週 1 回、自動で実行する | BR-02 | 初期 |
| FR-06 | 投稿の下書きを登録し、検査する（文字数、禁止語、URL の有無と、それによる費用） | BR-03, BR-04 | 初期 |
| FR-07 | 承認された下書きだけを投稿する。承認の記録がない下書きは投稿できない | BR-03 | 初期 |
| FR-08 | 投稿の結果（チャネル、投稿 ID、時刻、費用）を記録する | BR-01, BR-04 | 初期 |
| FR-09 | API の呼び出しごとに費用を見積もって記録し、月の上限を超える呼び出しを止める | BR-04 | 初期 |
| FR-10 | 1 つの下書きを、複数のチャネルに投稿する | BR-02 | 将来（Threads を足すとき） |
| FR-11 | スマホのアプリから承認する | BR-02 | 将来（Google Cloud へ移すとき） |
| FR-12 | 計測の成功・失敗をログファイルに残し、運営者が後から確かめられるようにする | BR-01, BR-02 | 初期 |

## 0.4 非機能要件（NFR）

| ID | 区分 | 要件 | 上位 |
| --- | --- | --- | --- |
| NFR-01 | セキュリティ | 認証情報は OS の安全な保管場所（初期：macOS キーチェーン）から読む。リポジトリ・ログ・エラー文に出さない | BR-06 |
| NFR-02 | セキュリティ | 取得した数字と下書きは、リポジトリの外に保存する | BR-06 |
| NFR-03 | セキュリティ | 公開リポジトリに個人情報や別の活動の名前が入らないよう、CI とコミット前のフックで禁止語を検査する | BR-03, BR-06 |
| NFR-04 | セキュリティ | 投稿する文章も、送信の直前に禁止語を検査する。1 つでも一致したら投稿しない | BR-03 |
| NFR-05 | 信頼性 | 同じ週に計測が 2 回動いても、集計が重複しない（再実行しても結果が同じ） | BR-01 |
| NFR-06 | 信頼性 | 同じ下書きを二重に投稿しない | BR-03, BR-04 |
| NFR-07 | 費用 | 月の費用の上限を設定できる（初期値：500 円） | BR-04 |
| NFR-08 | 移植性 | チャネル・保存先・動かす場所・承認の場所・認証情報の置き場所を、それぞれ部品の差し替えで変えられる | BR-05 |
| NFR-09 | 保守性 | Python、uv、ruff、ty を使う。外部の API を呼ばずにすべてのテストを実行できる | BR-05 |
| NFR-10 | 規約 | 各チャネルの API 利用規約と自動化のルールに従う | BR-03 |

## 0.5 コアユースケース（UC）

| ID | ユースケース | 流れ（概要） |
| --- | --- | --- |
| UC-01 | 週次の計測 | 自動で起動 → チャネルごとにアカウントと直近の投稿の数字を取得 → 保存 → 集計をノートに書き出す |
| UC-02 | 承認つきの投稿 | 下書きを登録 → 検査の結果と費用を表示 → 運営者が承認 → 投稿 → 結果を記録 |
| UC-03 | 費用の確認 | 今月の費用の合計と上限までの残りを表示する |

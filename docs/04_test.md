# 4. テスト仕様

- すべてのテストは外部の API を呼ばない（NFR-09）。X の応答は、記録した JSON を返す偽物の通信で置き換える。テスト中はネットワークへの接続を禁止する。
- 時刻は CMP-U03 Clock を固定して与える。
- CI で毎回すべて実行する。

## 単体（TC-U）

| ID | 対象 | 確かめること | 設計 |
| --- | --- | --- | --- |
| TC-U01 | E02 文字数 | ASCII は 1、日本語・絵文字は 2、URL は 23、280 ちょうどは合格、281 は不合格 | DD-06 |
| TC-U02 | E02 URL の判定 | `https://…` と `example.com` の形を URL とみなし、注意（費用の差）を出す | DD-06 |
| TC-U03 | E02 禁止語 | 大文字・全角の違いがあっても一致する。理由に禁止語そのものが出ない。禁止語ファイルが空なら不合格 | DD-07 |
| TC-U04 | E03 換算 | ドル × 為替を 1 円単位に切り上げる | DD-08 |
| TC-U05 | E03 上限 | 上限ちょうどは許し、1 円でも超えたら拒否する | DD-08 |
| TC-U06 | E01 集計 | 同じ投稿を 2 回取得しても合計は 1 回分。月のアカウントの数字はその月の最後の値。並び順は同じ値でも一意 | DD-10、NFR-05 |
| TC-U07 | A01 署名 | OAuth 1.0a の署名が、RFC 5849 §1.2 の例（`MdpQcU8iPSUjWoN/UDMsK2sui9I=`）と一致する。URL に認証情報が出ない | DD-09 |
| TC-U08 | A01 項目名 | X の応答が共通の項目名に揃う。取れない項目は `None` | 02b §2b.3 |
| TC-U09 | A01 再試行 | GET は 429・5xx・タイムアウトで最大 2 回、2 秒・4 秒（±20%）待って再試行する。`x-rate-limit-reset` が 60 秒より先なら待たずに失敗する。429 以外の 4xx と POST は再試行しない | DD-09 |
| TC-U10 | A03 遷移 | 許す遷移だけが通り、それ以外は拒否される。同じ下書きを 2 回「送信中」にできない | DD-04 |
| TC-U13 | 保存先の可変性 | IMMUTABLE の表（`account_snapshots`・`post_metrics`・`charges`）への UPDATE・DELETE がトリガーで拒否される。`drafts` の文章と指紋は更新できない。同じ主キーの保存は重複しない | DD-03 |
| TC-U11 | 指紋 | NFC の違いで指紋が変わらない。文章が 1 文字変われば変わる | DD-05 |
| TC-U14 | 直和型 | すべての状態に名前がある。理由のない Fail は作れない。検査の結果がエラーと注意に分かれる | DD-02 |
| TC-U12 | U01 Secret | `repr`・`str`・ログのどれにも値が出ない | DD-13 |

## 結合（TC-I）：Manager と偽物の ResourceAccess

| ID | コールチェーン | 確かめること |
| --- | --- | --- |
| TC-I01 | CC-01 | 計測で、取得 → 保存 → 費用の記録 → 集計の書き出しが行われる |
| TC-I02 | CC-01 | 見積もりが上限を超えると、API を呼ばずに終わり、失敗が記録される |
| TC-I03 | CC-01 | 取得の途中で失敗したら、取れた分だけ保存し、集計は書き換えない |
| TC-I04 | CC-02 | 禁止語を含む下書きは「不合格」で保存される |
| TC-I05 | CC-03 | 指紋が一致しないと承認されない |
| TC-I06 | CC-04 | 承認のない下書きは投稿されない。投稿の前に禁止語の再検査が行われる |
| TC-I07 | CC-04 | API が失敗したら「失敗」になり、再送できる。「送信中」は再送を拒否する |
| TC-I08 | CC-05 | 今月の合計・上限・残りが正しい |

## アーキテクチャ（TC-A）

| ID | 確かめること |
| --- | --- |
| TC-A01 | 契約の import が利用規則（01 §1.6 の 1〜6、DD-01 の import の規則）を守る。標準ライブラリの `ast` で import を読み取って検査する。違反を仕込んだファイルを検出できることも確かめる |
| TC-A02 | 実装（構成要素のパッケージの中のモジュール）を import するのは、同じ構成要素と `composition.py` だけ |
| TC-A03 | 実行時の依存が標準ライブラリだけ（`pyproject.toml` の `dependencies` が空） |

## 総合（TC-S）：CLI を通して

| ID | 確かめること |
| --- | --- |
| TC-S01 | `draft add` → `approve` → `publish` の流れで投稿され、終了コードが 0 |
| TC-S02 | 業務上の拒否は 1、使い方の誤りは 2、外部の失敗は 3 で終わる |
| TC-S03 | `measure` で集計のファイルが作られ、2 回目で全体が置き換わる |

## 非機能（TC-N）

| ID | 確かめること | 要件 |
| --- | --- | --- |
| TC-N01 | 公開リポジトリに禁止語・許可していないアドレスがない（`scripts/check_privacy.py`） | NFR-03 |
| TC-N02 | ログの全行に、認証情報と下書きの全文が含まれない | NFR-01、FR-12 |
| TC-N03 | 保存先と設定ファイルの場所が、リポジトリの外 | NFR-02 |
| TC-N04 | ワークフローの Action が SHA で固定され、権限が読み取りだけ（`scripts/check_workflows.py`） | NFR-03 |

## 変動性シナリオ（TC-R）

| ID | シナリオ | 確かめること |
| --- | --- | --- |
| TC-R01 | 2 つ目のチャネル（偽物）を足す | Manager と Engine を変えずに、計測と集計が 2 つのチャネルで動く（VOL-01） |
| TC-R02 | 保存先を、メモリ上の偽物に差し替える | Manager と Engine を変えずに動く（VOL-09） |
| TC-R03 | 単価表と為替を変える | コードを変えずに、見積もりと上限の判定が変わる（VOL-02、VOL-06） |

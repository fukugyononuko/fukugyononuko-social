## ID の規則
- ID は一度振ったら番号を変えない。廃止するときは削除せず「廃止」と書く。
- 設計を変える PR では、関係する ID の記述とトレーサビリティ表を同じ PR で更新する。
- 状態は「初期」（初期リリースで実装）と「将来」（置き場所だけ設計し、実装しない）の 2 種類。
- 構成要素は `CMP-Xnn`（X = C: Client、M: Manager、E: Engine、A: ResourceAccess、U: Utility）。

### 詳細設計のチェックリスト
- ER 図
- 表の一覧と、表ごとの MUTABLE（UPDATE・DELETE がある）／ IMMUTABLE（INSERT だけ）。IMMUTABLE はトリガーで守る
- 外部とのやり取りごとの再試行（回数、待ち時間、揺らぎ、制限のヘッダー）と冪等性
- 図（mermaid）は、push の前に検証する
- 状態によって持つ項目が変わる型は直和型（`type X = A | B`）にし、`match` と `assert_never` で網羅性を ty に検査させる（[フェーズ 1](retrospectives/2026-10-12-phase1.md) T-01）
- 契約と実装は構成要素ごとのパッケージに並べ、import の規則をアーキテクチャテストで検査する（同 T-02）
- 費用が繰り返し発生する処理では、各反復の直前に「累積額 + 次の 1 単位の上限」で確認しているか（[フェーズ 3](retrospectives/2026-10-14-phase3.md) T-01）
- 一緒に成立すべき複数の書き込みは、同じトランザクション境界・同じ保存先の仕組みに入り、途中で失敗したときにすべて戻るか（同 T-02）
- 外部の成功の応答を読めないときの扱い。特に、取り消せない操作では「結果がわからない」として扱うか（同 T-03）

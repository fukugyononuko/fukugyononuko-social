# 設計ドキュメント

アーキテクチャは Juval Löwy『Righting Software』の **The Method**（変動性に基づく分解）に従う。説明は表を中心に短く書く。

| # | ドキュメント | 内容 | 主な ID |
| --- | --- | --- | --- |
| 0 | [要件定義](00_requirements.md) | ビジネス要件、機能要件、非機能要件、コアユースケース、未決事項 | BR / FR / NFR / UC / OPEN |
| 1 | [概要設計](01_overview.md) | 範囲、変動性の分析、階層構成、利用規則 | VOL / CMP / RES |
| 2a | [基本設計・外部](02_basic_external.md) | コマンド、外部インターフェース | CLI / EIF |
| 2b | [基本設計・内部](02_basic_internal.md) | 構成要素の責務と契約、コールチェーン | CMP / CC |
| 3 | [詳細設計](03_detailed.md) | 型、データスキーマ、アルゴリズム、エラー処理 | DD |
| 4 | [テスト仕様](04_test.md) | 単体・結合・アーキテクチャ・総合・非機能・変動性シナリオ | TC |
| T | [トレーサビリティ表](traceability.md) | 上流から下流への対応と、その逆引き | — |

## ID の規則
- ID は一度振ったら番号を変えない。廃止するときは削除せず「廃止」と書く。
- 設計を変える PR では、関係する ID の記述とトレーサビリティ表を同じ PR で更新する。
- 状態は「初期」（初期リリースで実装）と「将来」（置き場所だけ設計し、実装しない）の 2 種類。
- 構成要素は `CMP-Xnn`（X = C: Client、M: Manager、E: Engine、A: ResourceAccess、U: Utility）。
